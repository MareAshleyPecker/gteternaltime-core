# 附：这些东西在游戏里怎么用
> [← 返回目录](<../GTM开发教程(编写中).md>)

这一节写给**玩家 / 整合包作者**，不讲代码；每条只讲「在哪、点什么、看到什么」。

## 高级终端（GTMThings 的 `gtmthings:advanced_terminal`）

- **界面**：手持终端右键打开。窗口 372×274 —— 左边竖着一列 8 行设置（文本输入 / `[◀] 值 [▶]` 步进器 / ✓ 复选框），
  右边**上下两块**可滚动的分级方块列表（`AdvancedTerminalBehavior.java:87-116`）。
- **两块面板不一样**：上面那块每组一行，「方块 + [▶]」点一下循环到下一档；下面那块每档一行，「方块 + ✓」勾上即选定。
  两者写的是**同一份** NBT（`gtet_terminal.group_prefs`），所以在上面切过之后，下面那块对应行的勾会跟着变
  （`:366-368`、`:704-708`、`:722-739`）。
- **`group_prefs` 是干什么的**：「每个分级组（线圈 / 能源仓 / 超频仓 / 线程仓 / 维护仓…）你选了哪一档」。
  自动搭建时这一格放什么，就按它决定（`TerminalSettings.resolve`，`TerminalSettings.java:135-149`）；
  没选过就用候选里的第一档。
- **不扫描也能选**：5 类静态组（线圈 / 能源仓 / 超频仓 / 线程仓 / 维护仓）由 `TerminalGroupSeeder` 每 tick 补进主手终端的 NBT
  （`TerminalGroupSeeder.java:54-64`、`TerminalStaticGroups.java:28-39`），所以一打开面板就有东西可选，不必先扫一次。
- **扫描 / 搭建**：对着控制器 **Shift + 右键** = 按结构自动搭建，同时把这次规划出来的分级组写进终端 NBT
  （`AdvancedTerminalBehavior.java:122-148`、`AdvancedTerminalBehaviorMixin.java:45-77`）；面板就是读这份数据列出来的。
- **绑 AE**：勾上设置里第 5 行「使用 AE 物品」（NBT `IsUseAE`）后，自动搭建缺的方块会从**你背包里那台 AE2 无线终端**
  所在的网络里抽 —— 前提是那台无线终端已经按 AE2 的常规方法绑好了无线接入点（`AdvancedBlockPattern.java:587-598`）。
  ⚠️ GTET 自己另写的那套「把终端直接绑到无线接入点」（`TerminalSettings.linkAe` / `AeGridLink` / `StructureBuilder`）
  目前**没有游戏内入口**（项目里没有调用点），别找它。
- **另外三行设置**：第 6 行镜像搭建、第 7 行模块搭建（`0` = 主结构，`N>0` = 第 N 套结构，取不到就静默退回主结构）、
  第 8 行拆除模式（反向按结构拆掉，不放置）。
- 这两块面板可以在 `config/gtetcore/gtetcore-common.toml` 里用 `dev.tierSelectEnabled` 关掉（默认开，
  `GTETConfig.java:194-197`）。

## 模块化测试机（`gtetcore:modular_test_machine`）

- 面板**右侧**有一个模块槽（`ETModularTestMachine.kt:88-98`），往里面放**一个**模块物品：
  **金 = MK1、钛 = MK2、中子素 = MK3**（`:41-46`）；放别的、或不放 = 等级 0 = **结构直接不成立**。
- 换模块 = **换结构**：MK1 是 3×3×3、MK2 是 5×5×5、MK3 是 7×7×7（`:111-115`）。所以要「换档」就是把模块换成高一档的金属。
- 面板会显示三行：模块等级、模块方块数、**配方电压上限**（`:72-80`）。上限 = 基础档（MK1 → LV、MK2 → HV、MK3 → IV）
  **再加上**「结构里的模块方块数 ÷ 8」（`:48-57`）—— 也就是结构越大，允许跑的配方电压越高。
- EMI 里这台机器有**三页**结构预览，用 `P:` 按钮翻页（`ETModularTestMultiblocks.kt:61-63`）；想看哪档长什么样不用自己搭。

## 线程仓（`gtetcore:thread_hatch_*`）

- 一共 8 档，名字里直接写着线程数：**ZPM 4 / UV 8 / UHV 16 / UEV 32 / UIV 64 / UXV 128 / OpV 256 / MAX 512**
  （`ETThreadHatches.kt:120-129`）——「线程数」就是「最多同时跑几条配方」。
- 装上默认就是**上限全开**；右键这个仓打开面板：第一行是名字（带电压等级与线程数），第二行是一个数值输入框
  （`ThreadHatchPartMachine.kt:94-106`）。
- 输入框**只能往下调**（1 ~ 该档上限），设定会存进方块存档、拆了重装也记得。
- ⚠️ **下调不会砍掉已经在跑的线程** —— 只是不再为多出来的槽位开新线程，已经在跑的那些自己跑完
  （`:38-41`，理由：线程一旦开了就已经扣过料，砍掉等于吞材料）。
- ⚠️ 线程仓**只加在 GTET 自己的多方块上**（`ETTestMultiblocks.kt:90-100`），GTM / GCYM 原有多方块插不进去；
  并行仓才是「GTM / GCYM 的多方块也认」的那个。
- 一台机器的总处理次数上限 ≈ **线程数 × 并行仓的并行数**（每条线程各自再吃一遍并行倍率，`IThreadHatch.kt:11-14`）。

## 超频仓（`gtetcore:overclock_hatch_*`）

- 一共 17 档，**名字里就写全了规格**，例如英文 `UV Overclock Hatch (8× Speed / ×4 Energy)`、
  中文「UV 超频仓（8× Speed|×4 Energy）」（`ETOverclockHatches.kt:178` / `:191`）。
- 读法：**每消耗 1 级超频，配方耗时 ÷S、EUt ×(E×S)**（`IOverclockHatch.kt:29-42`）。
  所以 `S` 越大越快；同一个 `S` 系列里 `lossy4 → lossy2 → perfect → saving` 就是「同样的速度，电越来越省」
  （`perfect` = 不加价，`saving` = 越超越省）。表在 `ETOverclockHatches.kt:119-145`。
- **只有两档带额外说明行**：`4x_lossy4`（"看起来并不好用"）与 `1024x_saving_max`（"屌爆啦！！！"）——
  这两档的 tooltip 末尾会多一行文案（`:122-123`、`:143-144`）；其余档只有名字 + GTM 自带的「部件不可共享」。
- 右键这个仓打开面板：**只有名字一行**（没有输入控件，规格都在名字里，`OverclockHatchPartMachine.kt:61-67`）。
- ⚠️ 一台机器**只认一个**超频仓（找到第一个就返回），而且结构里通常也只允许放 1 个
  （`MixinOverclockingLogic.java:193-199`、`MixinPredicatesAutoAbilities.java:73-75`）。
- 它的作用是**整体替换**这台多方块的普通超频 —— 装上之后就不是「每级 ÷2 耗时 ×4 耗电」那套了。
  单方块机器与聚变堆不吃它（`:185-191`）。

## 并行仓（`gtetcore:parallel_hatch_*`）

- GTET 自己的并行仓覆盖 **IV ~ MAX 十档**：IV 32 / LuV 128 / ZPM 512 / UV 2048 / UHV 8192 / UEV 16384 /
  UIV 65536 / UXV 262144 / OpV 1048576 / MAX 4194304（`ETParallelHatches.kt:57-68`）。
- **怎么选档**：装上哪一档，就拿到那一档的并行上限（默认就是上限）；右键这个仓打开面板，那格数值输入框可以再往下调
  （1 ~ 该档上限），改完下一轮就按新值取数（`ETParallelHatchPartMachine.kt:52-62` / `:70-79`）。
- ⚠️ 注意 UEV 那档**只有 UHV 的两倍**（其余档是 ×4）—— 这是确认过的字面值，不是漏改（`:55`）。
- 这台仓用的是 GTM 原生的 `PARALLEL_HATCH` 能力，所以 **GTM / GCYM 的多方块也认得它**；反过来，
  GTM 自带的 IV~UV 四档并行仓已被 GTET 删掉配方并隐藏，低档请用 GTET 这一套（`:32-41`）。
